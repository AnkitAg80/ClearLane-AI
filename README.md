# ClearLane AI

ClearLane AI is an AI-driven parking congestion intelligence system for detecting illegal parking hotspots, estimating their congestion impact, forecasting short-term risk, and recommending targeted enforcement deployment.

The project is built around the problem of parking-induced congestion. Instead of showing only where violations happened, ClearLane AI converts violation, road-capacity, time-series, and spatial context into a Congestion Impact Index (CII), forecasts next-3-hour CII, and uses that forecast to guide officer allocation.

## What The App Does

ClearLane AI provides a command-center dashboard with:

- A street-level command map with H3 hotspot overlays.
- Location-first search suggestions for roads and hotspot places.
- Forecast, after-deployment, officer, relief, and score map modes.
- An officer deployment optimizer.
- Hotspot explanation panels.
- AI trust and evidence views for model behavior and limitations.
- Optional Mappls / MapMyIndia basemap support with fallback to the existing street map.

## Environment Setup

Create a local `.env` file from `.env.example`:

```powershell
Copy-Item .env.example .env
```

Mappls / MapMyIndia keys are optional for backend scoring, but useful for the partner basemap:

```env
MAPPLS_CLIENT_ID=your_client_id_here
MAPPLS_CLIENT_SECRET=your_client_secret_here
MAPPLS_MAP_SDK_KEY=your_map_sdk_key_here
```

Do not commit real keys.

## Install Dependencies

From the project root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

For local development, tests, geospatial processing, and LightGBM training, install the larger development dependency set:

```powershell
pip install -r requirements-dev.txt
```

Then install frontend dependencies:

```powershell
cd frontend
npm install
cd ..
```

## Run The Data Pipeline

The pipeline requires the development dependency set:

```powershell
pip install -r requirements-dev.txt
```

To prepare artifacts without retraining the LightGBM model:

```powershell
.\.venv\Scripts\python.exe -m src.pipeline --phase3
```

To force LightGBM training:

```powershell
.\.venv\Scripts\python.exe -m src.pipeline --phase3 --train
```

To skip OSM road context for a faster local run:

```powershell
.\.venv\Scripts\python.exe -m src.pipeline --no-roadctx --phase3
```

The `--mappls` flag currently exists for compatibility, but active CII scoring uses OSM-derived road capacity context.

## Run The Dashboard

Build the frontend:

```powershell
cd frontend
npm run build
cd ..
```

Start the FastAPI app:

```powershell
.\.venv\Scripts\python.exe -m app.app
```

Open:

```text
http://127.0.0.1:8501
```

The FastAPI server serves the built React frontend from `frontend/dist`.

```powershell

```

Keep the FastAPI backend running on `http://127.0.0.1:8501` so API calls continue to work.

## Key Concepts

### Congestion Impact Index

CII estimates congestion impact from parking violations using vehicle type, violation severity, validation confidence, road capacity, peak-hour pressure, and chronic recurrence. Details are in `docs/CII_METHOD.md`.

### Next-3-Hour Forecast

The model predicts `target_next_3h_cii`, the expected CII pressure in each H3 cell over the next three hours. Details are in `docs/NEXT_3H_MODEL.md`.

### LightGBM Models

The project trains:

- `LGBMRegressor` for continuous next-3-hour CII prediction.
- `LGBMRanker` for relative hotspot prioritization.

The final deployment score blends regression and rank signals.

### Deployment Optimization

The optimizer assigns available officers across high-priority cells and estimates CII relief. The dashboard separates raw forecast from after-deployment remaining CII so users can compare expected risk before and after targeted enforcement.

## Troubleshooting

If the dashboard says the frontend build is missing, run:

```powershell
cd frontend
npm run build
cd ..
```

If the map shows `Fallback street map`, check that `MAPPLS_MAP_SDK_KEY` has Web Map SDK access enabled in the Mappls console and is allowed for the current local or deployed domain.

If Vercel reports a Python bundle size error, confirm it is installing `requirements.txt`, not `requirements-dev.txt`. Heavy training packages are intentionally kept out of runtime deployment.

If the deployed Vercel page says `Frontend build not found`, confirm `vercel.json` is present in the committed branch. It runs `npm ci && npm run build` inside `frontend/` before routing requests to the FastAPI app.

If the app cannot load command data, confirm that `data/processed/` contains the required parquet, CSV, JSON, and model artifacts.

If GitHub rejects a push because of large CSV files, make sure raw datasets remain inside the git-ignored `dataset/` folder and are not tracked.
